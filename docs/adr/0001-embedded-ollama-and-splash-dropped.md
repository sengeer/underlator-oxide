# ADR 0001: Embedded Ollama manager и splash — dropped

- **Статус:** accepted
- **Дата:** 2026-11-22
- **Связанные документы:** `.docs/ARCHITECTURAL_PLAN_TAURI_RUST_DUAL_MODE_V1.md`, `docs/adr/0002-rag-deferred.md`

## Контекст

Underlator работает с внешним экземпляром Ollama: пользователь указывает base URL в настройках, а manage models перечисляет, устанавливает и удаляет модели по этому URL. В MVP на Rust / Tauri 2 продукт не содержит embedded Ollama manager: runtime не скачивается, не устанавливается и не обновляется приложением.

Splash-экран исторически существовал только для ожидания запуска embedded runtime и отображения его прогресса. Без embedded runtime у splash нет продуктовой задачи: окно Tauri и React UI показываются сразу, а состояние Ollama проверяется обычным запросом к настроенному URL.

Возможное SaaS-направление и отказ от привязки к одному инференсу делают embedded-менеджер нежелательной архитектурной зависимостью: продукт должен одинаково работать с локальным Ollama, корпоративным сервером и будущими провайдерами через provider trait.

## Решение

Embedded Ollama manager и splash-цепочка **dropped**. Они не входят в MVP, не считаются отложенной работой и не восстанавливаются в рамках текущей архитектуры.

Маркеры `TODO(splash)` и консервированные модули splash остаются в коде как исторический след. Их семантика: «restoration not planned; requires new change + ADR update». Возврат splash UI или embedded-менеджера требует нового OpenSpec change и обновления этого ADR, а не локальной правки по маркеру.

## Последствия

- Пользователь запускает Ollama самостоятельно; приложение не управляет его установкой и не показывает splash-progress.
- Настройки ограничены провайдером `Ollama`, полем `url` и manage models по этому URL.
- Консервированные splash-модули и маркеры `TODO(splash)` не удаляются, но и не оживляются без нового change и ADR update.
- Архивные change не редактируются: их исторические формулировки остаются как есть.

## Рассмотренные альтернативы

- **Оставить embedded manager и splash в backlog.** Отклонено: backlog создаёт ложное ожидание возврата и провоцирует вернуть UI без исследования и нового плана.
- **Сохранить splash как «загрузочный экран» без embedded runtime.** Отклонено: у экрана нет данных и задачи, он добавляет задержку и ложную зависимость от lifecycle Ollama.
- **Поддержать embedded runtime как opt-in.** Отклонено в рамках MVP: это отдельный продуктовый сценарий с установкой бинарников, обновлениями и контролем версий.
