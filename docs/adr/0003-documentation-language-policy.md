# ADR 0003: Политика языка документации — EN-канон и RU-зеркало

- **Статус:** accepted
- **Дата:** 2026-11-22
- **Связанные документы:** `docs/DESKTOP_TAURI.md`, `docs/DESKTOP_TAURI_RU.md`, `README.md`, `README_RU.md`

## Контекст

Desktop-документация описывает сборку, native prerequisites, troubleshooting, канонические артефакты и матрицу `verified` / `unverified`. Внешние читатели и спецификации ожидают англоязычный канонический документ, а русскоязычная аудитория проекта — полноценное зеркало. Один русскоязычный файл не покрывает оба сценария, а два независимых документа быстро расходятся по командам и статусам.

## Решение

`docs/DESKTOP_TAURI.md` — **EN-канон**, `docs/DESKTOP_TAURI_RU.md` — **RU-зеркало**. Оба файла содержат языковой переключатель друг на друга:

- EN-файл ссылается на `DESKTOP_TAURI_RU.md`;
- RU-файл ссылается на `DESKTOP_TAURI.md`.

Правило синхронизации: **сначала EN, затем RU**. Любое изменение команд, prerequisites, troubleshooting или матрицы вносится в EN-канон и только после этого зеркалится в RU. EN-файл остаётся каноническим путём для спек. `README.md` ссылается на EN-файл, `README_RU.md` — на RU-файл.

## Последствия

- Изменение desktop-документации — всегда пара файлов; проверка синхронности входит в DoD.
- Матрица `verified` / `unverified` переносится без изменения статусов: Fedora 44 AppImage — `verified`, macOS и Windows — `unverified`.
- Новые языки добавляются отдельным ADR и отдельным зеркалом, а не правкой пары.

## Рассмотренные альтернативы

- **Оставить только русскоязычный документ.** Отклонено: внешние читатели и спеки ожидают EN-канон.
- **Вести два независимых документа.** Отклонено: команды и матрица расходятся, синхронизация становится ручной и непроверяемой.
- **Один двуязычный файл.** Отклонено: он хуже читается, ломает якоря и усложняет поддержку.
